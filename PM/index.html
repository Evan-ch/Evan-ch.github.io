# 软考高项未知知识点记录、错题

  • CPS是智能制造的核心
  • 代码走查 技术风格，编写规范
  • 螺旋模型更强调风险分析
  • 验收时检查代码 设计文档一致性等， 综合检查
  • 计算机软件文档规范 规定 需求节点内，作为本阶段的工作成果， 需求规格说明书、初步用户手册 数据要求说明
  • 数据分析是入侵检查系统的核心
  • 机房设计规范 风 40 电阻 10欧
  • 政府项目采购文件保存15年
  • 政府项目不是必须公开招标
  • 中标通知书发出后，中标人也可以放弃项目
  • 完整的绩效报告包括 进度情况、成本使用情况、团队成员绩效情况、项目存在问题的解决措施和对项目的预测
  • 设计评审属于质量控制活动
  • 大型及复杂项目实施跟踪和控制的过程中，重点关注 绩效报告的有效性并处理好项目的变更
  • 大型IT项目的范围管理 在需求清洗后，对项目计划进行调整，按照计划进行范围管理
  • 企业战略，包含三个层次：公司战略，业务战略、职能战略
  • 综合布线子系统： 设备间子系统、工作区子系统、管理子系统；
  • 隐蔽工程必须要旁站监理
  • 质量保证为过程改进创造了条件
  • 鉴定是一个正式的过程，通过这个过程决定产品是否符合他的规格说明，是否可以在正式环境中使用
  • 评审：需求评审、设计评审、概念评审、测试评审、安装和验收评审、软件用户手册评审
  • 相同设备用交叉线，不同设备用直连线
  • 监理单位为了获得监理任务，在项目奖励招标阶段编制的文件为 监理大纲
  • 在需求开发中，完成需求验证过程后将确定需求基线
  • 在大型项目实施和工作过程中，最重要的是要关注绩效和变更情况
  • 千兆以太网与10/100M以太网具有相同的帧格式
  • 主机房不宜设置外窗
  • UML 用例图是对一组动作序列的描述
  • 招投标中对结果质疑，对方答复后不满意要在15日内投诉
  • 著作权中的 署名权 修改权 保护作品完整权是不受时间限制的
  • 政府小项目，也不能少了 可行性研究报告的编制和报批
  • 可行性研究报告：概述、需求确定、现有资源、技术方案、进度计划、项目组织、效益分析、写作方式、结论、投资估算
  • 投标书中不准公开项目标底
  • 沟通管理计划不一定要得到客户的一直认可才能实施
  • 项目的相关性：时间、知识、逻辑三个维度
  • 识别相关质量标准，是编制质量规划的首要工作
  • 软件的内部和外部质量属性划分为6个特性，分别是功能性、可靠性、易用性、效率、可维护性、可移植性
  • 需求分析阶段 输出：软件需求规格说明书、数据要求说明、初步的用户手册
  • 面向数据流的分析方法是结构话的分析方法
  • 开发人员职责定义：管理文档；
  • 职责描述：开发文档；
  • 软件产品的所有文档的签署不允许代签
  • 数据可靠性校验--数据链路层功能
  • 项目干系人管理主要目的是避免干系人的严重分歧
  • 可行性研究报告要包括项目计划
  • 废标后，采购人应当将废标理由通知所有投标人
  • 封闭式问题：用来确认信息的正确性
  • 探寻式问题 用来澄清之前谈过的主题与信息
  • 开放式问题 鼓励应征者详细回答，表达情绪
  • 假设式问题 用来了解解决问题的方式
  • 不可抗力不能进行经济索赔
  • 基线主要属性：名称、标识符、版本、日期
  • 软件生命周期中，软件度量的三个维度：项目度量、产品度量、过程度量
  • 配置管理的三种基线：功能基线、分配基线、产品基线
  • 一个对象只能有一个类，一个类可以有多个对象
  • 系统总线：是用于计算机内部各个不同设备中共享的数字信号传输通路
  • 管理和商务是信息系统集成项目实施成功的保障
  • 需求分析3个阶段：1、需求提出 2、需求描述 3、需求评审
  • 数据仓库主要用于支持决策管理
  • 五级安全级别：
  • 1、用户自主保护级
  • 2、系统审计保护级
  • 3、安全标记保护级
  • 4、结构化保护级
  • 5、访问控制保护级
  • 安全策略是全方位的安全防御体系
  • 管理子系统是连接干线子系统和水平子系统之间的桥梁
  • 项目先论证，再评估！
  • 总预算包含管理储备，项目成本不包含管理储备、 基线不包含管理储备和活动预留
  • 配置管理的4个活动：配置项标识、配置项状态报告、配置审计、配置项控制
  • 需求分配是软件架构师要完成的主要任务之一
  • 需求分析阶段拟定了系统的范围、目标和要求，系统各模块的算法在详细设计阶段设计
  • 技术评审（同行评审）确定意图的合适性和是否达到使用要求，
  • 数据流图包括 数据流、加工、数据存储、外部实体
  • 综合布线 长度= (长+短)/2信息点比例 水晶头 信息点*4
  • UML 需求描述中的吧“包含”“组成”“分成一-不符”等词常常意味着存在聚集关系。
  • 基线识别不是基线定义中的内容.
  • 建立基线的条件、受控制项、批准基线变更的权限 是基线定义中的内容
  • 基线配置项是技术方面（设计文档、代码）的，非基线配置项是计划文档、报告等
  • 系统方法论不包括易用性原则
  • 配置项修正完成后需要再次评审才能变成正式发布状态
  • webservice 3个角色 服务请求者 服务提供者 服务注册中心
  • 软件包质量要求包括三部分：产品描述要求 文档要求 程序和数据要求
  • GB/T 11456-2006（术语） 规定了配置管理的三种基线：功能基线、分配基线、产品基线
  • 质量保证计划属于开发文档，开发文档、管理文档、产品文档
  • 项目章程要明确项目在组织中的地位
  • 提交多个投标方案，直接废标
  • 项目风险识别所采用的技术：因果图、流程图、影响图
  • 大型项目执行过程中 范围和质量容易失真

# 成文信息数据库表命名规范

  1. 临时表 TMP_用途/表名_日期 --用于导入数据或者拉取数据基表或中间表，不自动清理，仅人工清理
  2. 备份表 BAK_表名_6位日期，如果当天有多个后面加a,b,c,d... 用于做批量数据更新时备份原表，一个月自动清理一次
  3. 历史表 HIS_表名_根据转储频率和数据量按月份或者年度转储历史表 .. 禁止清理

# 税额计算公式

已知：数量，含税单价, 税率 一次性计算出 含税金额（价税合计）/ 不含税单价 / 不含税金额 / 税额

  • 含税单价 * 数量 = 含税金额,
  • round(含税单价 / (1 + 税率), 10) = 不含税单价,
  • round(含税单价 * 数量 / (1 + 税率), 2) = 不含税金额,
  • 含税单价 * 数量 - (round(含税单价 * 数量 / (1 + 税率),2)) = 税额
